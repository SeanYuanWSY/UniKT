# Batch 42（2026-10-07：能力排除臂无泄漏调参重跑——Codex #19 遗留闭环）

## 动机

Codex Run A P1-7 / 纠错 #19：`a17_ability_decompose_v2.py` 的调参存在标签回代——prior 用**全部** evidence 行拟合，而每第 5 行 evidence 又被用作调参伪 holdout，调参行的自身标签经 prior 回到自己的预测里（Codex 反例：α=1 选择集 AUC=1、α=0 为 0，即泄漏可完全支配选择）。当前正文已把该臂降级为"代理未被选中，不排除能力机制"（措辞层修复）；本批用无泄漏调参重跑，判定该臂是"干净排除"还是"真有信号"。

注：`ability_before` 本身无泄漏（hist 在预测后才 append）；v2 的唯一泄漏通道是 prior。v2 的 eval pass（真实 holdout）不受此泄漏影响——受影响的只是 α 的选择。

## 实验设计（`a17_ability_decompose_v3.py`）

1. **无泄漏调参先验**：调参行 = 每第 5 个非 holdout 非 A1 evidence 行（同 v2 规则）；`prior_tuning` 只用其余 evidence 行（全学生）拟合——调参行标签不可能进入 prior_tuning。
2. **选择**：调参行上 per-student AUC（prior_tuning + ability_before 混合，α∈{0,.25,.5,.75,1}）取均值最大者。
3. **评估**：α 冻结后跑真实 holdout（A1 排除）；`prior_final`=全量 evidence 重拟合（标准 tune-then-refit，holdout 未动）；另报 prior_tuning 敏感性与 α=0/α=1 两端点。
4. **v2 复现锚**：同批用泄漏 prior（全量）重跑选择——必须复现 v2 的 α*=1.0（三域）。

## 预注册门（写于运行前）
